- 빌드를 막던 죽은 코드를 걷어냈다. `/standings` 페이지, `/api/games/today`,
  `/api/games/[id]/ai-preview`, `/api/games/[id]/ai-review`, 그리고 이들만 쓰던
  `AiContent`·`GameCard`·`TeamLogo`·`StatusBadge`·`LoadingSpinner` 컴포넌트와
  `lib/prisma.ts` 더미. 전부 어디서도 참조하지 않았고 prisma 미설치로 타입체크를
  막고 있었다.
- `prisma/schema.prisma` 와 `prisma.config.ts` 는 이후 DB 도입을 위해 남겨 두고
  tsconfig 의 exclude 로만 뺐다.
- `lib/openai.ts` 의 `dangerouslyAllowSVG` 를 제거했다. next/image 옵션이 OpenAI
  클라이언트 설정에 잘못 들어가 있었다.

이제 `npm run build` 가 통과한다.

데이터 가용성은 2026-09-26 에 네이버 API 를 직접 찔러 확인했다. 확인 내용은

### 0. 뎁스(WAR) 가 없는 시즌 처리 — 먼저

- [ ] **완료**

**왜.** 네이버 선수 기록에 WAR 이 2017년부터만 있다. 그 전 시즌은 전력 추정의
뎁스 항(가중치 30%)이 모든 팀에 같은 값으로 들어가, 팀을 구분하지 못하고 전력
격차만 70% 로 압축한다. 그 결과 `docs/PREDICTION.md` 에 적은 "18시즌 검증,
모델 1순위 15/18" 은 서로 다른 세 모델을 섞어 낸 값이라 그대로 믿을 수 없다.

확인한 값:

| 시즌 | 타자 WAR 합 | 투수 WAR 합 | 뎁스 상태 |
| :--- | ---: | ---: | :--- |
| 2008~2013 | 0.0 | 0.0 | 없음. 전 팀 뎁스 승률 0.299 로 동일 |
| 2014~2016 | 0.0 | 110~143 | 투수만 |
| 2017~2026 | 205~239 | 130~150 | 정상 |

**무엇을.**

- [ ] 팀 WAR 이 전부 0 이면 뎁스 항을 빼고 남은 항끼리 가중치를 재정규화한다
      (피타고리안 .45 / 실제 .25 -> .643 / .357). 상수로 때우지 않는다
- [ ] 타자 WAR 만 없는 2014~2016 은 투수 WAR 만으로 뎁스를 쓰되, 그 사실을
      응답과 화면에 표시한다
- [ ] 응답에 뎁스 적용 여부(`depthAvailable` 같은 필드)를 담아 화면에서 구분한다
- [ ] 검증을 다시 돌린다. 뎁스가 온전한 2017~2025 9시즌을 주 결과로, 18시즌짜리는
      "뎁스 없는 모델" 로 따로 표기한다
- [ ] `docs/PREDICTION.md` 의 검증 절을 새 수치로 교체한다

**완료 조건.** 2010년 예측 응답에서 팀별 전력이 서로 다르고, 화면에 뎁스 미적용이
표시되며, `docs/PREDICTION.md` 의 검증 표가 어느 시즌 범위의 어떤 모델인지 분명하다.

### 1. 투구 로케이션 / 스트라이크존

- [ ] **완료**

**왜.** 경기 상세에 지금은 B/S/O 점만 있다. 중계 응답에 실제 투구 추적 데이터가
들어 있으므로, 추정이 아니라 측정값으로 존 그림을 그릴 수 있다.

**데이터 근거.** `/schedule/games/{id}/relay` 의 `textRelays[].ptsOptions` 에
릴리스 좌표(`x0,y0,z0`), 속도 벡터(`vx0,vy0,vz0`), 가속도(`ax,ay,az`),
플레이트 통과 좌표(`crossPlateX`, `crossPlateY`), 타자별 존 상하한
(`topSz`, `bottomSz`), 타석 방향(`stance`) 이 있다.

2026-09-24 롯데-LG 경기 25구로 계산을 검증했다. 구속 124~151 km/h,
플레이트 높이 0.58~3.67 ft 로 실제 범위와 맞는다.

- 구속: `sqrt(vx0^2+vy0^2+vz0^2)` 를 ft/s -> km/h (x 0.3048 x 3.6)
- 플레이트 높이: `y(t)=crossPlateY` 가 되는 t 를 풀어 `z(t)` 를 구한다
- 좌우: `crossPlateX` 를 그대로 쓴다. 존 폭은 좌우 약 0.83 ft

**무엇을.**

- [ ] `ptsOptions` 파싱과 구속·높이 계산을 lib 로 분리하고 단위를 명시한다
- [ ] `relay` 는 페이지 단위라 한 번에 25구 정도만 온다. `no` 로 페이징해
      한 경기 전체를 모으는 경로를 만든다
- [ ] 스트라이크존 SVG 컴포넌트. 타자별 존 상하한을 반영하고 존 통과 여부로 색을 나눈다
- [ ] 경기 상세에 붙인다. 진행 중이면 최근 타석, 끝난 경기면 투수별 집계
- [ ] 좌표계와 계산식을 `docs/DATA-SOURCES.md` 에 적는다

**완료 조건.** 끝난 경기 상세에서 투수별 투구 분포가 존 위에 그려지고, 구속이
KBO 실제 범위 안에 들어온다.

### 2. 선수 상세 페이지

- [ ] **완료**

**왜.** 선수 검색과 리더보드는 있는데 선수를 눌러도 갈 데가 없다. 지금 비어 있는
가장 기본적인 자리다.

**데이터 근거.** 선수 개인 상세 엔드포인트는 403 이지만,
`/statistics/categories/kbo/seasons/{year}/players` 를 연도별로 불러
`playerId` 로 묶으면 커리어가 만들어진다. 2026 시즌 구자욱(`62404`) 을
2015~2026 까지 추적해 확인했다.

고급 지표(wRC+, wOBA, WPA, BABIP, WAR)는 2017년부터만 있다. 그 전 시즌 행에는
비워 두고 이유를 적는다. 추정으로 채우지 않는다.

**무엇을.**

- [ ] `/players/[id]` 페이지와 API
- [ ] 연도별 기록 표. 타자·투수 각각. 2017년 이전은 고급 지표 열을 비운다
- [ ] 리더보드와 검색 결과에서 선수 이름을 이 페이지로 연결한다
- [ ] 연도별 호출이 19회라 캐시를 둔다. 지난 시즌은 길게, 현재 시즌은 짧게

**완료 조건.** 검색에서 선수를 눌러 커리어가 뜨고, 2017년 이전 행의 빈 칸에
이유가 표시된다.

### 3. 매직넘버 / 트래직넘버

- [ ] **완료**

**왜.** 시즌 막바지에 가장 많이 보는 숫자다. 순위와 잔여 일정이 이미 있어서
새 API 없이 계산만 붙이면 된다.

**무엇을.**

- [ ] 팀별 우승 매직넘버, 포스트시즌 진출 매직넘버, 탈락 확정(트래직) 넘버
- [ ] 이미 확정된 팀은 확정으로 표시한다
- [ ] 순위표 또는 우승 확률 화면에 넣는다
- [ ] 잔여 경기가 순연으로 덜 편성돼 있으면 매직넘버가 흔들린다. 이 전제를 밝힌다

**완료 조건.** 현재 순위 기준 매직넘버가 KBO 공식 발표와 일치한다.

### 5. 순위 변동 그래프

- [ ] **완료**

**왜.** 시즌 중 순위가 어떻게 움직였는지 보여주는 화면이 없다.

**데이터 근거.** 일자별 순위 API 는 없다.
`/statistics/categories/kbo/seasons/{year}/teams/ranks` 는 빈 응답을 준다.
일정 전체를 날짜순으로 집계해 직접 만들어야 한다. `head-to-head.ts` 가 이미
같은 방식으로 정규시즌 구간을 찾아내므로 그 코드를 재사용한다.

**무엇을.**

- [ ] 일정에서 날짜별 누적 승패를 쌓아 일자별 순위를 만든다
- [ ] 순위 변동 선 그래프. 팀 상징색을 쓴다
- [ ] 기록실에 연도별로 붙인다

**완료 조건.** 시즌 마지막 날 순위가 그 시즌 최종 순위와 일치한다.

### 하지 않기로 한 것

- **선수 사진** — 네이버가 Referer 로 핫링크를 막아 두었다. 우회하지 않는다
- **팀 로스터 전용 API, 선수 개인 상세 API, 구장 API** — 전부 403
- **부상자 명단, 트레이드, 라인업 예고** — 네이버 API 에 없다
- **순연 경기를 추정으로 채우기** — 편성일이 공지되면 자동으로 들어온다.
  자세한 이유는 `docs/PREDICTION.md` 의 한계 절 참고
