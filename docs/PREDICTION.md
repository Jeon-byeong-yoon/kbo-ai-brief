# 우승 확률 예측

`/predictions` 에서 보는 숫자가 어떻게 나오는지, 그리고 얼마나 믿을 수 있는지 적는다.

## 먼저: 학습한 모델이 아니다

"과거 데이터로 우승을 예측하는 모델을 학습시킨다"는 접근은 이 문제에 쓸 수 없다.
**우승 사례가 시즌당 하나뿐이라 2008~2025 를 다 써도 18개**다. 팀 타율·팀 평균자책·
선수 뎁스를 피처로 넣으면 금방 10~20개가 되는데, 표본 18개에 피처 20개면 모델이
학습하는 게 아니라 외운다. 게다가

- 8구단에서 10구단으로 바뀌었고 (2013·2015년 확장)
- 2019년 공인구 변경으로 득점 환경이 크게 달라졌으며
- 18개 중 4개가 삼성 왕조(2011~2014)라 실질 독립 표본은 더 적다

그래서 **시뮬레이션**으로 간다. 학습은 우승이 아니라 경기 단위로 한다.

## 모델 상수는 측정했다

가정하지 않고 2008~2025 실제 경기에서 뽑았다.

| 상수 | 값 | 근거 |
| --- | --- | --- |
| 홈 승률 | **0.5196** | 정규시즌 9,732경기(무승부 제외) 중 홈 4,961승 4,586패 |
| 피타고리안 지수 | **1.80** | 140 팀-시즌에 대해 잔차가 최소가 되는 값 (RMSE 0.0268) |

둘 다 야구 통계에서 통용되는 값(홈 0.54 안팎, 지수 1.83)과 가까워서 측정이
제대로 됐다고 본다. 정규시즌 구간은 `docs/DATA-SOURCES.md` 에 적은 방법으로 가려냈다.

## 전력 추정

팀마다 세 가지를 구해 섞는다.

1. **피타고리안 승률** — `득점^1.8 / (득점^1.8 + 실점^1.8)`.
   승패 기록보다 팀 실력을 잘 나타낸다
2. **실제 승률** — 실제로 거둔 성적. 운도 포함돼 있다
3. **뎁스 승률** — 소속 선수 WAR 합을 리그 평균 기준으로 환산.
   `0.5 + (팀WAR - 리그평균WAR) / 144`. 절대 수준이 아니라 평균과의 차이만 쓴다.
   선수 데이터는 `pageSize=500` 으로 팀당 24~41명씩 전체 로스터를 받는다

```
전력 = 0.5 + (피타 x 0.45 + 실제 x 0.25 + 뎁스 x 0.30 - 0.5) x 0.8
```

마지막 0.8 은 평균 회귀다. 세 추정치 모두 완벽하지 않으므로 .500 쪽으로 20% 당긴다.

### 뎁스를 쓸 수 없는 시즌

네이버는 WAR 을 모든 시즌에 주지 않는다. 전 연도를 확인한 결과는 이렇다.

| 시즌 | 타자 WAR 합 | 투수 WAR 합 | `depthCoverage` |
| :--- | ---: | ---: | :--- |
| 2008~2013 | 0.0 | 0.0 | `none` |
| 2014~2016 | 0.0 | 110~143 | `pitcher-only` |
| 2017~2026 | 205~239 | 130~150 | `full` |

없는 값을 0 으로 받아 그대로 쓰면 전 팀의 뎁스가 같아진다. 그러면 가중치 30% 짜리
항이 팀을 구분하지 못하면서 전력 격차만 70% 로 압축한다. 그래서 두 가지를 한다.

- **뎁스를 아예 쓸 수 없으면(`none`) 그 항을 빼고 남은 둘로 가중치를 재정규화한다**
  (피타고리안 .643 / 실제 .357). 상수 .5 를 30% 섞는 것과는 다르다. 그건 평균 회귀를
  한 번 더 거는 것과 같아서 격차를 또 줄인다
- **리그 평균을 빼서 중심을 .500 에 맞춘다.** 이러지 않으면 WAR 총량이 시즌마다
  달라 뎁스 항이 리그 전체를 위아래로 민다. 실제로 투수 WAR 만 있는 2014~2016 은
  리그 평균 뎁스가 .392, 2017년 이후는 .531 이었다

`depthCoverage` 는 API 응답에 담기고, `full` 이 아니면 화면에 그 사실을 표시한다.

### 정규시즌 순위는 그 시즌 규정을 따른다

정규시즌 1위를 가릴 때는 네이버의 `wra` 값을 쓴다. 무승부를 승률에 넣을지는 KBO
규정이 시대마다 달랐는데 이 값이 그 규정을 따르기 때문이다. 2009년이 대표적이다.

| 팀 | 성적 | `wra` | 승/(승+패) |
| :--- | :--- | ---: | ---: |
| KIA | 81승 48패 4무 | **.609** | .628 |
| SK | 80승 47패 6무 | .602 | **.630** |

직접 승/(승+패) 로 계산하면 SK 가 1위로 뒤집힌다. 실제 2009년 정규시즌 1위는 KIA 였다.

팀 기록의 `ranking` 필드는 쓰지 않는다. 그건 포스트시즌까지 반영한 최종 순위다.
2015년 `ranking=1` 은 79승의 두산(한국시리즈 우승)이고, 88승으로 정규 1위였던 삼성은
`ranking=2` 로 나온다.

화면의 표에 이 세 값과 전력을 모두 그대로 보여준다. 어느 팀의 확률이 왜 그렇게
나왔는지 숫자로 따라갈 수 있어야 한다는 뜻이다. 예를 들어 2026 한화는 실제 승률이
.419 인데 피타고리안이 .496, 뎁스가 .528 이라 전력은 .489 로 잡힌다.
득실차에 비해 승수가 적었던 팀이라는 게 드러난다.

## 시뮬레이션

두 팀의 승부는 log5 로 계산하고, 측정한 홈 승률만큼 오즈에 곱해 홈 이점을 넣는다.

```
P(A승) = (a - a x b) / (a + b - 2 x a x b)
```

한 번의 시뮬레이션은 이렇게 돈다.

1. 남은 정규시즌 경기를 모두 치른다
2. 최종 승률로 순위를 매긴다
3. 포스트시즌을 치른다
   - 와일드카드: 4위 홈 최대 2경기. 4위는 1승만 해도 올라가므로 5위는 2연승해야 한다
   - 준플레이오프: 3위 vs 와일드카드 승자, 5전 3선승
   - 플레이오프: 2위 vs 준PO 승자, 5전 3선승
   - 한국시리즈: 정규 1위 vs PO 승자, 7전 4선승
4. 우승 팀을 기록한다

기본 20,000회 반복한다. 난수는 시드를 고정해서 같은 입력이면 같은 결과가 나온다.

확률 합계로 자체 검증한다. 우승 100%, 한국시리즈 진출 200%, 포스트시즌 진출 500%,
정규시즌 1위 100% 가 나와야 한다.

## 검증 — 과거 시즌

각 시즌의 최종 성적을 넣고 포스트시즌을 시뮬레이션한 뒤 실제 우승팀과 대조했다.
배포되는 코드를 그대로 호출해서 얻은 결과다.

뎁스를 쓸 수 있는 시즌과 아닌 시즌은 사실상 다른 모델이므로 나눠서 본다.
**주 결과는 뎁스가 온전한 2017~2025 다.**

| | 2017~2025 (9시즌) | 2008~2016 (9시즌) | 전체 18시즌 |
| :--- | :---: | :---: | :---: |
| 뎁스 | 온전 | 없음 / 투수만 | 섞임 |
| 모델 1순위가 실제 우승팀 | **8 / 9 (89%)** | 7 / 9 (78%) | 15 / 18 (83%) |
| 정규 1위가 우승 (기준선) | 8 / 9 (89%) | 8 / 9 (89%) | 16 / 18 (89%) |
| 실제 우승팀에 부여한 평균 확률 | **49.7%** | 51.3% | 50.5% |

무작위로 찍으면 10% 다.

### 빗나간 세 번

- **2015** — 실제 두산 우승(정규 3위). 모델은 삼성을 1순위로 두고 두산에 7.5%
- **2018** — 실제 SK 우승(정규 2위). 모델은 두산을 1순위로 두고 SK 에 20.5%
- **2009** — 실제 KIA 우승(정규 1위). 모델은 SK 를 1순위로 두고 KIA 에 27.7%.
  뎁스가 없는 시즌이라 피타고리안 비중이 커졌는데, SK 의 득실차(.626)가
  KIA(.587)보다 좋아 순위가 뒤집혔다

### 솔직하게 적어 둘 것

**2017~2025 에서 모델의 1순위는 9시즌 모두 정규시즌 1위와 같았다.** 즉 이 모델은
누가 우승 후보인지를 고르는 데서는 "정규 1위가 우승한다"는 기준선에 아무것도
더하지 못한다. 더하는 것은 **그 후보에게 얼마의 확률을 줄지**다. 2019년 두산 41.0%,
2021년 KT 43.5% 처럼 접전인 해에는 낮게, 2023년 LG 62.3% 처럼 확실한 해에는 높게
준다. 기준선은 언제나 100% 라고 말하는 것과 같다.

2015·2018 처럼 하위 시드가 우승한 해는 어떤 모델도 맞히기 어렵다. 그런 해에도
7.5%, 20.5% 라는 0 이 아닌 확률은 줬다.

가중치를 과거 결과에 맞춰 조정하면 적중률은 올릴 수 있다. 하지만 그게 바로 맨 위에서
피하려 한 과적합이라 하지 않았다. 지금 가중치는 야구 통계에서 통용되는 근거
(피타고리안이 승패 기록보다 예측력이 좋다)에 따라 정했고, 화면과 이 문서에 그대로
공개한다.

## 데이터 신선도

네이버 응답은 `next: { revalidate }` 로 캐시한다 (진행 중인 시즌 900초). 이건
stale-while-revalidate 라서 기한이 지나도 낡은 값이 먼저 나가고 갱신은 뒤에서 돈다.
요청이 없으면 갱신도 없고, 갱신이 실패하면 낡은 값이 조용히 남는다. 실제로 개발 서버를
오래 띄워 뒀을 때 11일 전 순위로 확률이 계산된 적이 있다.

그래서 응답에 두 시각을 따로 담고 화면에 같이 띄운다.

- `generatedAt` — 시뮬레이션을 돌린 시각. 매 요청 새로 찍히므로 **신선도 지표가 아니다**
- `dataAsOf` — 네이버가 말하는 "아직 안 치른 가장 이른 경기" 날짜. 팀 기록의
  `nextScheduleGameId` 앞 8자리에서 뽑는다. 캐시가 낡으면 이 값도 같이 과거에 머무르므로
  데이터의 나이를 그대로 드러낸다
- `staleDays` — `dataAsOf` 가 오늘보다 며칠 뒤처졌는지. 0 보다 크면 화면에 경고가 뜬다

`nextScheduleGameId` 는 어느 연도를 조회하든 그 팀의 "지금" 다음 경기를 가리킨다.
2015 시즌을 조회해도 2026년 경기가 돌아온다. 그래서 진행 중인 시즌에만 쓰고, 지난
시즌은 `dataAsOf` 를 `null` 로 둔다.

캐시를 아예 없애는 대신 드러내는 쪽을 먼저 택한 이유는 `no-store` 로 돌리면 화면 한 번에
네이버를 여러 번 때리기 때문이다. 근본 대응인 태그 기반 무효화는 `docs/DEPLOYMENT.md`
참고.

## 한계

- 부상·트레이드·선수 기용 변화를 모른다. 시즌 누적 성적만 본다
- 선발 로테이션을 구분하지 않는다. 단기전에서 에이스 등판 여부는 큰 변수인데 반영이 없다
- 팀 WAR 은 네이버가 주는 선수 목록의 합이라 전체 로스터와 정확히 같지는 않다
- 동률 처리는 난수로 가른다. 실제 KBO 는 상대전적 등으로 가린다
- 2007년 이전은 데이터가 없어 검증 표본을 더 늘릴 수 없다. 뎁스까지 온전한 시즌은
  2017년 이후 9시즌뿐이라 주 검증 표본이 작다
- 우천 순연 후 편성일이 아직 공지되지 않은 경기는 일정에 없어 시뮬레이션에서 빠진다.
  2026-09-26 기준 잔여 56경기 중 46경기만 일정에 올라와 있었고, 팀별로도 고르지 않았다
  (두산 0경기 누락, KT·KIA·LG·롯데 각 3경기). 빠진 몫을 평균 상대와의 중립 경기로
  메우는 방법도 있지만 쓰지 않는다. 없는 일정을 지어내면 근거가 흐려지고, 순연 경기는
  어차피 편성일이 공지되면 다음 갱신 때 그대로 들어오기 때문이다. 진행 중인 시즌은
  15분마다 다시 읽으므로 경기가 끝나는 대로 승패와 잔여 경기가 함께 갱신된다
